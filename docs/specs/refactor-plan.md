# 改造方案：拆骨 + 数据落地 + 产品功能

功能名：refactor-plan
更新日期：2026-09-14
文档类型：方案稿（等主人点头后开工）

## 一、现在的问题（都已实测）

1. 店面是一个文件：`index.html` 8319 行 / 466KB，340 个函数、134 个功能项、23 段脚本。
2. 改一处容易碰坏别处：本次只改品牌名就动了 20 处，写错一个括号全站白屏。
3. 只有店门有测试（`gate/test_gate.py`，26 个），店面本身零测试。
4. 数据全在浏览器本地（localStorage）：换设备、清缓存就没了；店门服务器上没有作品备份。
5. 仓库 196MB，其中 118MB 是语音模型（`models/`），跟着代码一起进了 Git。

## 二、第一步：拆骨（把大文件拆成小文件）

目标：功能一模一样，但代码分成若干小文件，改一处不影响别处。

阶段与顺序（每步单独验证，随时可停、可回退）：

1. 拆「配置与技能表」：`XLX.PARKED`、`XLX.SKILLS`、`XLX.PROVIDERS`、`XLX.SEARCH_ENGINES` 抽成 `src/config.js`。
2. 拆「工具函数」：`XLX.util`（渲染、Toast、ZIP、下载）抽成 `src/util.js`。
3. 拆「模型与设置」：`XLX.llm`、设置页各部分抽成 `src/settings.js`。
4. 拆「技能与工具页」：技能市场、工具箱各页抽成 `src/skills.js`、`src/tools.js`。
5. 拆「对话与工坊」：对话、软件工坊抽成 `src/chat.js`、`src/studio.js`。
6. 保留 `index.html` 作为唯一入口，用 `<script src="src/xxx.js">` 引入，顺序与原脚本顺序一致。

验证方式（每步都做）：
- 每个新文件 `node --check` 通过。
- `index.html` 里所有 `<script>` 块 `node --check` 通过。
- 店门 26 个测试全过。
- 手动点一遍：对话、技能市场、工具箱、软件工坊、设置。

回退方式：每一步单独提交；出问题回退上一步即可。

风险：拆分属大手术，必须一步一提交、一步一验证；不允许一次拆完再看。

## 三、第二步：数据落地（作品存到服务器）

目标：朋友的作品换设备也能接着用；主人能看到谁做了什么。

1. 新增 SQLite 数据库：用户、房间、作品、操作记录四张表。
2. 新增接口：`POST /api/works` 存作品、`GET /api/works` 列作品、`GET /api/works/<id>` 取作品。
3. 权限：朋友只能读写自己房间的作品；主人可读全部。
4. 隐私：作品内容默认只主人和朋友自己可见；不记录任何 API Key。
5. 兼容：浏览器本地数据保留，首次登录时提示可一键上传到服务器。

验证方式：接口测试 + 用两个不同账号交叉验证「看不到对方的作品」。

## 四、第三步：产品功能（把店做成小铺子）

1. 朋友注册 → 各自房间 → 作品一键上线到 `/zuopin/<账号>/`（已有基础）。
2. 用量控制：每天生成次数上限（配置项，默认值待主人定）。
3. 邀请码：只由主人发；换新后旧码作废（已有基础）。
4. 作品列表页：朋友能看到自己的作品、复制链接、重新编辑。
5. 是否收费：**本轮不做**，等主人明确指示。

## 五、暂缓功能（本次已摘入口）

- 已摘：「AI 生图」「AI 剧作」相关 10 个技能 + 工具集两个页签 + 设置里两个板块 + 创作中心整页 + 对话里的剧作自动跳转。
- 实现代码全部保留在 `index.html` 里，由一处开关控制：`XLX.PARKED = { image: true, drama: true }`。
- 恢复方式：把 `image` / `drama` 改成 `false`，并清空 `XLX.PARKED_SKILLS`。
