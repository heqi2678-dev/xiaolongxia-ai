# 需求文档：作品导出成压缩包

功能名：export-zip
更新日期：2026-09-12
文档类型：需求稿（EARS）

## 简介

「作品导出成压缩包」指在软件工坊里把当前项目导出为一个 ZIP 文件，下载到本机后解压即可运行。

当前实现位于 `index.html`：

- 打包入口：`renderPack()`（`index.html:7151`）与 `downloadZip()`（`index.html:7130`）
- 压缩包生成：`XLX.util.ZIP.make()`（`index.html:1167`），只用浏览器内置能力，无外部依赖
- 文件下载：`XLX.util.download()`（`index.html:1155`）
- 项目存储：浏览器本地存储键 `XLX.K.PROJECT`，由 `load()` / `save()` 读写（`index.html:6827`、`index.html:6836`）

本文档描述该功能应当达到的行为。凡属现状说明的，都在验收标准里写明；凡属有待补齐的，也如实写出，不把未实现的行为当成已完成。

## 术语表

- **工坊**：软件工坊页面，AI 生成软件项目并提供预览、打包、上线的区域。
- **项目**：当前工坊里的一组文件，包含文件名与文件内容，保存在浏览器本地存储中。
- **压缩包**：导出的 ZIP 文件，含项目全部源文件与自动生成的辅助文件。
- **辅助文件**：导出时自动加入的 `README.md`、`start.bat`、`start.sh`。
- **白名单扩展名**：允许上线的网页文件扩展名，由 `gate/server.py` 的 `PUBLISH_EXTS` 定义。
- **EARS**：一条验收标准一句，句式固定、可直接测试。

## 需求

### 需求 1：一键导出压缩包

用户故事：作为工坊使用者，我希望点一下按钮就把当前项目导成压缩包，以便把作品带走、备份或放到别处运行。

验收标准：

1. 系统应提供「下载软件包 ZIP」按钮，按钮位于打包页面内。
2. 当使用者点击「下载软件包 ZIP」按钮，系统应在浏览器中生成一个 ZIP 文件并触发下载。
3. 系统应在压缩包内包含项目全部源文件，以及自动生成的 `README.md`、`start.bat`、`start.sh`。
4. 系统应把导出的压缩包命名为 `<项目名>.zip`。

### 需求 2：压缩包名安全

用户故事：作为工坊使用者，我希望压缩包名不因特殊字符出错，以便在任何系统上都能正常保存。

验收标准：

1. 当项目名含空格、斜杠、冒号、星号等字符时，系统应剔除非字母、非数字、非汉字、非连字符的字符后再命名。
2. 若项目名为空或剔完字符后为空，系统应使用 `project` 作为压缩包名。
3. 系统应保证压缩包名长度不超过 100 个字符。
4. 系统应保证压缩包只出现一次 `.zip` 后缀。

### 需求 3：与打包页面显示一致

用户故事：作为工坊使用者，我希望实际导出内容与页面列出的文件一致，以便确认没有漏文件。

验收标准：

1. 系统应在打包页面列出将要导出的每个文件名与体积。
2. 系统应在打包页面显示将要导出的文件总数，文件总数应等于项目文件数加辅助文件数。
3. 当使用者点击「下载软件包 ZIP」按钮，系统应导出的文件集合与页面列出的文件集合相同。
4. 若项目文件数为零，系统应在打包页面提示先做出项目，并不触发下载。

### 需求 4：二进制文件不得静默丢失

用户故事：作为工坊使用者，我希望图片等二进制文件也能进压缩包，以便解压后作品不缺素材。

验收标准：

1. 当项目文件内容为二进制数据（如 Blob、图片），系统应把该文件按原始字节写入压缩包。
2. 若某个文件无法写入压缩包，系统应在导出结果中列出该文件名并给出失败原因。
3. 系统不应在任何情况下静默跳过文件；被跳过的文件必须在页面提示中可见。
4. 系统应在导出前后核对写入文件数与页面列出的文件数一致。

### 需求 5：导出前给出体积信息

用户故事：作为工坊使用者，我希望导出前知道压缩包多大，以便判断下载是否费流量。

验收标准：

1. 系统应在打包页面显示每个文件的体积，以及全部文件体积合计。
2. 当体积合计超过 20 MB 时，系统应提示体积偏大并建议先精简素材。
3. 系统应在导出过程中显示进行中的提示，并保证页面操作不卡死。
4. 若导出耗时超过 5 秒，系统应持续显示进行中提示直到导出结束。

### 需求 6：离线与零依赖

用户故事：作为工坊使用者，我希望没有网络时也能导出，以便在弱网环境里带走作品。

验收标准：

1. 系统应在不访问外部 CDN、不加载第三方库的情况下生成压缩包。
2. 系统应在浏览器内置能力范围内完成压缩包生成，不在服务器上留副本。
3. 当导出过程中发生异常，系统应提示失败原因，并保留当前项目数据不丢失。
4. 系统应在异常之后仍可再次点击导出并成功生成压缩包。

### 需求 7：压缩包可正常解压

用户故事：作为工坊使用者，我希望压缩包在任何常见解压工具里都能打开，以便交给不懂技术的人也能用。

验收标准：

1. 系统应生成标准 ZIP 格式（含本地文件头、中央目录与结尾记录）。
2. 系统应为每个文件写入正确的 CRC32 校验值。
3. 系统应用 UTF-8 编码记录文件名，保证中文文件名在 Windows 上正常显示。
4. 系统应在压缩包内保留原有的目录层级。

### 需求 8：与「一键上线」的文件选择一致

用户故事：作为工坊使用者，我希望导出的文件与上线的文件来自同一份项目数据，以便两处结果一致。

验收标准：

1. 系统应让导出与上线读取同一份项目文件集合。
2. 当项目文件数超过 30 个，系统应在上线前提示文件过多，并说明导出不受此限制。
3. 当项目体积超过 5 MB，系统应在上线前提示体积过大，并说明导出不受此限制。
4. 系统应在压缩包内的 `README.md` 中写明解压后如何运行。

### 需求 9：单文件网页版单独导出

用户故事：作为工坊使用者，我希望还能只导出一个单文件网页，以便直接发给别人打开。

验收标准：

1. 系统应提供「仅打包网页版(单HTML)」按钮。
2. 当使用者点击「仅打包网页版(单HTML)」按钮，系统应导出内联后的 `index.html` 单文件。
3. 若项目中没有 `index.html`，系统应使用项目中的第一个文件作为主文件。
4. 当项目为空时，系统应提示先做出项目，并不触发下载。

## 非目标

- 不把打包放到服务器执行；压缩包只在浏览器内生成。
- 不改动上线接口的限额（30 个文件、5 MB），限额调整另开需求。
- 不在本需求范围内引入压缩算法（当前为只存储不压缩），是否改为压缩留待设计稿讨论。
- 不改动管家页、后厨页与店门登录逻辑。
