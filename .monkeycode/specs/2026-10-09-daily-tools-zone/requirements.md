# 需求文档：日常工具分区 + 短剧 Agent 对齐 LibTV

## 引言

在现有「短剧工作台」「电商工作台」两个顶层分区之外，新增第三个顶层分区「日常工具」。原短剧工作台中的「工具包」迁入「日常工具」；原「铜龙电商ai助手 Agent」通用对话迁入「日常工具」并更名为「日常ai助手 Agent」。短剧工作台保留一个独立对话入口「短剧 Agent」，其命名、结构与交互对齐 LibTV 的 Agent，并能感知与操作当前画布。整体主题与配色保持现状，不引入 LibTV 深色主题。

## 术语表

- **顶层分区（Zone）**：应用顶部的并列工作区，当前为「短剧工作台」「电商工作台」，本次新增「日常工具」。
- **短剧工作台**：AI 短剧创作分区，`src/drama/shell.js` 中的 `drama` 分区。
- **电商工作台**：电商创作分区，`src/drama/ecom/ecom.js` 中的 `ecom` 分区。
- **日常工具**：本次新增的第三个顶层分区，承载工具包与日常ai助手 Agent。
- **工具包**：`src/drama/toolkit.js` 视图，含软件工坊 / 工具箱 / 客户端下载三入口与技能墙。
- **短剧 Agent**：短剧工作台中独立存在的对话入口，命名、结构与交互对齐 LibTV Agent，并能感知与操作当前画布。
- **日常ai助手 Agent**：由原「铜龙电商ai助手 Agent」迁移并更名而来的通用对话入口。
- **对话引擎**：`index.html` 中的 `XLX.chat`，负责消息流、模型选择、联网、开发模式、指挥店员与历史存储。
- **LibTV Agent**：对齐参照（libtv.ai）。其 Agent 是对话式创作入口，能读取并修改当前工程/画布，并可调度子 Agent。本次仅对齐其结构与交互，配色保持工作台现状。

## 需求

### 需求 1：三个顶层分区并存

**用户故事：** 作为用户，我希望在短剧、电商之外有一个独立的「日常工具」分区，以便把日常通用能力与短剧创作分开。

#### 验收标准

1. WHEN 应用启动，系统 SHALL 在侧栏呈现三个顶层分区切换项：短剧工作台、电商工作台、日常工具。
2. WHEN 用户点击某个分区切换项，系统 SHALL 切换到该分区并把当前分区标识写入 localStorage 键 `xlx_zone`。
3. WHILE 当前分区为日常工具，系统 SHALL 在侧栏渲染日常工具分区的导航清单。
4. WHEN 应用重新加载，系统 SHALL 依据 `xlx_zone` 恢复上次分区。

### 需求 2：工具包迁入日常工具分区

**用户故事：** 作为用户，我希望短剧之外的工具集中到「日常工具」，以便短剧分区只保留创作主线。

#### 验收标准

1. 系统 SHALL 在日常工具分区导航中呈现「工具包」入口。
2. 短剧工作台导航 SHALL 呈现以下入口：新建项目、短剧 Agent、首页、项目、资产、TV Show、创作者挑战赛、3D-BOX、Blender 插件、版本更新记录。
3. WHEN 用户在日常工具中打开工具包，系统 SHALL 呈现软件工坊 / 工具箱 / 客户端下载三入口与技能墙，行为与迁移前一致。
4. 系统 SHALL 保留既有收藏与使用记录（localStorage 键 `xlx_home_fav`、`xlx_home_used`）。

### 需求 3：通用对话迁入日常工具并更名

**用户故事：** 作为用户，我希望原来的通用对话成为「日常ai助手」，与短剧专用的 Agent 分开，以便两侧对话互不干扰。

#### 验收标准

1. 日常工具分区导航 SHALL 呈现「日常ai助手 Agent」入口。
2. 系统 SHALL 为「日常ai助手 Agent」与「短剧 Agent」维护相互独立的对话历史。
3. WHEN 用户在「日常ai助手 Agent」输入需求，系统 SHALL 提供迁移前的通用能力：多平台模型选择、联网搜索、开发模式、指挥店员。
4. 系统 SHALL 将迁移前的既有对话历史归入「日常ai助手 Agent」。
5. 系统 SHALL 在日常工具分区的顶栏将页面标题呈现为「日常ai助手」。

### 需求 4：短剧 Agent 的命名、位置与画布感知

**用户故事：** 作为用户，我希望短剧分区里的 Agent 与 LibTV 的叫法一致，并能像 LibTV Agent 一样直接参与当前工程，以便在一个入口里完成短剧创作。

#### 验收标准

1. 系统 SHALL 将「短剧 Agent」实现为一个全新独立的短剧专属对话入口，与「日常ai助手 Agent」的实现相互独立。
2. 短剧工作台导航 SHALL 呈现名为「短剧 Agent」的入口。
3. 「短剧 Agent」入口 SHALL 位于「新建项目」之后。
4. WHILE 当前视图为短剧 Agent，系统 SHALL 将顶栏标题呈现为「短剧 Agent」，副标题描述其短剧创作能力。
5. WHILE 当前视图为短剧 Agent，系统 SHALL 在空态以「短剧 Agent」自称，并呈现短剧创作向的建议入口。
6. WHILE 存在当前工程（画布），系统 SHALL 让「短剧 Agent」感知该画布实况，并支持用户以自然语言直接对画布下达指令（与 LibTV Agent 直接参与当前工程的行为对齐）。

### 需求 5：短剧 Agent 对齐 LibTV 的结构与交互（配色不变）

**用户故事：** 作为用户，我希望短剧 Agent 的操作方式与 LibTV Agent 一致，以便获得一致的使用体验。

#### 验收标准

1. 短剧 Agent 页面 SHALL 采用对话式布局：可新建/切换对话、中部消息流、底部输入区。
2. 短剧 Agent 页面 SHALL 保持工作台既有主题与配色，SHALL NOT 引入 LibTV 的深色主题或 `#22d3ee` 等配色覆盖。
3. 系统 SHALL 使「短剧 Agent」的结构与交互对齐 LibTV Agent，其余视图 SHALL 保持既有主题与行为不变。

## 决策记录

1. 迁移前的既有对话历史整体归入「日常ai助手 Agent」；「短剧 Agent」从空历史开始。
2. 「短剧 Agent」采用全新独立实现（独立页面、独立对话存储），与「日常ai助手 Agent」共用底层模型调用能力但不复用其界面与对话引擎。
3. 「短剧 Agent」对齐 LibTV Agent 的结构与交互，但配色保持工作台现状（不引入 LibTV 深色主题）。
4. 「短剧 Agent」需感知当前工程画布，并复用既有画布感知能力 `XLX.drama.agent` 以实现对画布的直接指令（依据 LibTV Agent 直接参与当前工程的行为）。
