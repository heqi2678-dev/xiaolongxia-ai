### 2.4 后端新增结构（建议）

`gate/server.py` 已 2419 行，把电商逻辑继续堆进去会让单文件失控。建议新建包：

```
gate/ecom/
├─ store.py        # sqlite 表与 DAO（products/skus/media/shops/shop_groups/tasks/mappings/price_rules/pacing/compliance_reports）
├─ queue.py        # 任务队列 + Worker 线程 + 调度器（定时/分时）
├─ registry.py     # 适配器注册表与统一契约
├─ adapters/
│   ├─ base.py
│   ├─ source_1688.py
│   ├─ target_douyin.py
│   └─ mock.py     # 契约测试用
├─ pipeline.py     # 采集/处理/生成/铺货/改价编排
└─ api.py          # /dian/api/ecom/* 路由处理
```

`gate/server.py` 只保留 ecom 前缀的转发入口，业务进包。凭证加密存储需要一把服务端主密钥（现仓库无 KMS，方案待定）。

## 五、风险提示

- 平台资质是外部依赖，一期真机链路可能受审核周期阻塞，建议适配器层先以 mock 契约驱动。
- 去水印、重复铺货、跨店搬运是平台规则敏感区，设计稿已限定官方 API + 自有版权素材，实施时须守住。
- `gate/server.py` 单文件已大，电商逻辑务必分包，否则维护成本陡增。
- 商品库与短剧资产共用 IndexedDB 时须命名空间隔离，避免键冲突。
