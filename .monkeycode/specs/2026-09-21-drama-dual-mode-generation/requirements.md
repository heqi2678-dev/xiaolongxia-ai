# 需求文档 · 短剧生成双模式（逐镜 + 原生多镜）

## 引言

本需求为专业创作范式的工作台增加第二套视频生成路径。现有路径为「逐镜模式」：一个分镜一次请求，逐镜可重拍。新增路径为「整段模式」：把若干连续分镜合并成一次请求，提示词以时间段描述段内各镜，一次生成一整段连续视频，取得跨镜的人物、光影与镜头连贯。

两套路径共用同一份工程模型、角色库、参考图、时间轴与合成链路，用户按工程自行选择。整段模式接入火山方舟 Seedance 2.5（`doubao-seedance-2-5-260628`），沿用现有任务式接口 `POST /api/v3/contents/generations/tasks` 与轮询 `GET /api/v3/contents/generations/tasks/{id}`，成片地址取自 `content.video_url`。

现状要点（作为基线）：
- 生成编排：`src/drama/engine.js` 的 `generateShot`（单镜）与 `generateMany`（批量）。
- 视频适配器：`src/drama/adapters/video.js`，任务式提交与轮询，支持首帧、首尾帧、参考图。
- 角色与参考图：`src/drama/character.js` 的 `refGroupsForShot`、`refImagesForShot`、`refNote` 与 `buildVideoPrompt`。
- 时间轴：`src/drama/timeline.js` 的 `total`、`layout`、`shotAt`。
- 合成链路：`src/drama/compose.js` 与服务端 `gate/server.py` 的 `drama_compose`。

## 术语表

- **逐镜模式**：一个分镜对应一次生成请求的生成路径，沿用现有行为。
- **整段模式**：一个镜头段对应一次生成请求的生成路径。
- **镜头段**：整段模式下的生成单元，由若干序号连续的**分镜**组成，含段序号、段时长、段内分镜、段计划与段素材。
- **生成模式**：工程的生成路径选择，取值 `shot`（逐镜模式）或 `take`（整段模式）。
- **段计划**：镜头段内各分镜的起止时间表，由段内各分镜的**时长**依次累加得出。
- **段素材**：一个镜头段生成得到的单个视频，绑定到该镜头段。
- **局段重绘**：以段素材为参考视频、按时间段定向编辑段内某一区间的操作。
- **状态**：分镜与镜头段的生成状态，取值 `pending`、`generating`、`done`、`failed`。

## 需求

### 需求 1 · 生成模式选择

**用户故事：** 作为短剧创作者，我希望在每个工程上选择逐镜或整段生成，以便按题材与预算挑选合适路径。

#### 验收标准

1. 工作台应在创作台提供「逐镜模式」与「整段模式」的生成模式选择入口，并展示当前生效的生成模式。
2. 当用户切换生成模式时，工作台应将 `shotMode` 持久化到工程，并在后续生成中生效。
3. 当工程缺少 `shotMode` 字段时，工作台应按逐镜模式处理该工程。
4. 当用户切换生成模式时，工作台应保留工程内已生成的分镜素材与段素材。
5. 当生成模式为整段模式时，工作台应隐藏单镜生成与单镜重拍入口，并展示整段生成、整段重抽与局段重绘入口。

### 需求 2 · 镜头段分组

**用户故事：** 作为短剧创作者，我希望把连续分镜合并成镜头段，以便控制每一次生成的范围。

#### 验收标准

1. 工作台应按分镜序号连续的原则把分镜划入镜头段，同一分镜在同一时刻仅属于一个镜头段。
2. 工作台应把镜头段的段时长取值为段内各分镜时长之和。
3. 工作台应把段时长限定在下限 4 秒与硬上限 30 秒之间，并以可调的分段目标时长作为分段参考，分段目标默认 15 秒。
4. 当候选镜头段的段时长超过硬上限时，工作台应把该候选段拆分，使每个镜头段的段时长落在下限与硬上限之间。
5. 当末尾候选段的段时长小于下限时，工作台应把该候选段并入相邻段。
6. 当单个分镜的时长超过硬上限时，工作台应提示该分镜无法参与整段生成并阻止发起。
7. 当用户调整分段目标时长时，工作台应重新计算镜头段边界，并保留与既有段签名一致的段素材。
8. 当用户调整某分镜的时长时，工作台应更新该分镜所在镜头段的段时长与段计划，并在段时长越界时提示重新分段。
9. 当工程为整段模式时，工作台应在时间轴上以段边界标记镜头段范围。

### 需求 3 · 整段生成

**用户故事：** 作为短剧创作者，我希望一次生成一整段连续视频，以便取得跨镜一致的画面。

#### 验收标准

1. 当用户对某镜头段发起生成时，工作台应向所选视频 provider 提交一次请求，请求时长取该镜头段的段时长。
2. 工作台应在请求提示词中按段计划的时间段描述段内各分镜的画面、运镜与台词，并附入该镜头段内各角色的**参考图**分组与角色对应说明。
3. 工作台应在请求中以角色参考图作为参考素材提交，并按「参考生视频」任务类型配置参数。
4. 工作台应在段内存在台词时请求有声视频，使段内对白与口型由同一次生成产出。
5. 当生成成功时，工作台应把返回视频作为段素材绑定到该镜头段，并把该镜头段与其段内分镜的状态置为 `done`。
6. 当生成进行中时，工作台应对同一镜头段的重复发起进行抑制，并在完成后恢复交互。
7. 当生成失败时，工作台应保留该镜头段的既有段素材，并把错误原因写入该镜头段，展示可重试入口。
8. 当视频模型档位未配置时，工作台应展示配置引导；用户选择继续时按「未配置回退」产出占位段素材并标注回退来源。

### 需求 4 · 局段重绘

**用户故事：** 作为短剧创作者，我希望只重绘段内不满意的时间区间，以便省去整段重抽。

#### 验收标准

1. 工作台应在整段模式下为段内每个分镜提供局段重绘入口，并把该分镜的段内起止时间写入编辑意图。
2. 当用户发起局段重绘时，工作台应以段素材作为参考视频、按「视频编辑」任务类型配置参数，并保持输出比例与时长与段素材一致。
3. 当局段重绘成功时，工作台应替换该镜头段的段素材，并保持段时长与段计划不变。
4. 当段素材时长落在 4 至 30 秒之外时，工作台应阻止局段重绘并提示重新生成该段。
5. 当局段重绘失败时，工作台应保留原有段素材，并把错误原因写入该镜头段。
6. 当用户修改段内某分镜的时长时，工作台应重新计算段计划并提示段素材与段计划不一致。

### 需求 5 · 逐镜模式保持

**用户故事：** 作为短剧创作者，我希望逐镜模式的行为不受整段模式影响，以便继续精确返工单镜。

#### 验收标准

1. 当生成模式为逐镜模式时，工作台应按现有单镜生成与单镜重拍行为执行，仅变更该分镜的素材与状态。
2. 当用户在逐镜模式下对已修改时长的分镜执行重拍时，工作台应使用修改后的时长参数。
3. 工作台应在两个生成模式下共用同一份角色库、参考图、模型档位与合规校验结果。

### 需求 6 · 段素材切分与时间轴对齐

**用户故事：** 作为短剧创作者，我希望整段成片在时间轴上仍按分镜对齐，以便配音与字幕逐镜校准。

#### 验收标准

1. 当镜头段生成成功时，工作台应按段计划把段素材映射到段内各分镜，并为每个分镜记录段内起止时间。
2. 工作台应在时间轴上按段内起止时间呈现段内各分镜的区间，并叠加段边界标记。
3. 当分镜存在字幕时，工作台应以该分镜的段内起止时间作为字幕对齐基准。
4. 工作台应在整段模式下从段素材取得配音音轨，并在用户关闭原生音频时改用逐镜语音合成。

### 需求 7 · 合成与导出

**用户故事：** 作为短剧创作者，我希望两个模式都能产出成片与素材包，以便交付与二次剪辑。

#### 验收标准

1. 当工程为整段模式时，合成应按段计划从段素材裁出段内各分镜的片段，并按分镜顺序拼接成片。
2. 当工程为整段模式时，导出素材包应包含段素材文件、段计划清单、配音文件、字幕文件与分镜清单。
3. 工作台应在成片上保留 AI 生成标注，并在两个模式下执行同一套合规校验。
4. 当合成或导出缺少段素材时，工作台应提示待补齐的镜头段并保留其余产物。

### 需求 8 · 数据兼容与迁移

**用户故事：** 作为既有用户，我希望升级后仍能打开原有工程，以便不丢失已有草稿。

#### 验收标准

1. 当工作台加载既有工程时，工作台应补齐 `shotMode`、`takes` 与分段目标等缺失字段，并按逐镜模式处理缺失 `shotMode` 的工程。
2. 当既有工程含已生成的分镜素材时，工作台应保留这些素材并在逐镜模式下继续可用。
3. 当工作台在整段模式下打开含既有分镜素材的工程时，工作台应保留这些素材并在切换回逐镜模式后可用。
4. 当工作台在整段模式下打开工程时，工作台应按现有分镜时长生成镜头段集合。

## 已确认决策

| 决策项 | 结论 |
|---|---|
| 分组方式 | 自动按时长上限分段，分段目标默认 15 秒、用户可调，硬上限 30 秒、下限 4 秒 |
| 段内返工粒度 | v1 即支持局段重绘：以段素材为参考视频，按时间段定向编辑 |
| 时长控制 | 段时长严格等于段内分镜时长之和，由段计划给出段内切点 |
| 音频来源 | 整段模式优先使用 Seedance 2.5 音视频联合生成的有声视频，用户可切换为逐镜语音合成 |

## 依赖与约束

- 整段模式依赖 Seedance 2.5 的任务类型与参数约束：
  - 参考生视频：`content` 中至少一个 `reference_image`，`ratio` 与 `duration` 不受特殊限制。
  - 视频编辑：`content` 中至少一个 `reference_video` 且提示词表达编辑意图，`ratio` 必须为 `adaptive`，`duration` 必须为 `-1`，参考视频时长必须为 4 至 30 秒。
  - 首帧/首尾帧：`content.role` 取 `first_frame` 或 `last_frame`，`ratio` 必须为 `adaptive`，输出比例随首帧。
- 当前 API 分辨率档位为 480P 与 720P，整段模式默认取 720P。
- 云端模型依赖用户自备 API Key，Key 只存本地，不写入仓库、不上传服务端。
- 现有测试基线须保持通过：`node --test tests/drama.test.js`、`NODE_PATH="$(npm root -g)" node tests/drama-e2e.js`、`cd gate && python3 -m unittest test_gate`。
