# 小龙虾 LibTV 化 · 总方案（细化定稿）

- 定稿日期：2026-09-22
- 范围：店门（`/dian/`）前端 + 网关 `gate/server.py`
- 不含：管家页（`/`，`tonglong-ui`，独立服务）
- 本版已完成步骤去重，修订记录见附录 A

## 0. 一句话

把小龙虾按三个大层改造成 LibTV 形态，每层只做本层的事；模型池作为贯穿线持续铺满；真 3D 满血版后置可选。

## 1. 总原则

1. 分层推进：一层只做一层的事，改地基时不碰界面。
2. 不交叉、不重复（本版已去重）。
3. BYOK：用户自填厂商钥匙，平台不垫资。
4. 管家（`/`，`tonglong-ui`）全程排除。
5. 静态文件改完即生效，无需重启服务。

## 2. 三层总览

| 层 | 名字 | 目标 | 出层标志 |
|---|---|---|---|
| 一 | 地基层 | 钥匙与模型统一 | 钥匙从多把合并为少数几把；对话、短剧用起来和现在一样 |
| 二 | 工作台层 | 三个台换 LibTV 长相 + 新能力 | 新长相、新能力全部到位 |
| 三 | 3D-BOX（AI 满血） | 导演工具一次做全 | 工具可用 |
| 门外 | 真 3D 满血 + 工程类 + 非工程类 | 天花板项 | — |

## 3. 第一层 · 地基层

**范围**：只动店门内的钥匙与模型，界面和功能用起来跟现在一样。
**不做**：管家不进、不查、不动。

### 现状：四本账各存一份

| 用在哪 | 存哪 | 结构 |
|---|---|---|
| 对话·平台单配置 | `xlx_settings` | `provider` + `providers[]` 每平台一把 |
| 对话·模型库 | `xlx_models` | 每条 `{vendor, base, key, model}` |
| 店员 Hermes 大脑 | `xlx_clerk_brain` | `keys{}` 按平台 |
| 短剧四类 | `xlx_drama_settings` | `adapters.{image,video,tts,lipsync}` |

### 步骤

**1.1 建设钥匙库**
- 新建 `xlx_vendor_keys`，按厂商分组，一份钥匙全站共用
- 设置页新增「厂商钥匙库」区块，作为主入口；旧输入框保留兜底

**1.2 四处消费改造**（把四处取钥匙的来源改成钥匙库）
- 短剧四类：`adapters.image / video / tts / lipsync`
- 对话·平台单配置：`xlx_settings.providers`
- 对话·模型库：`xlx_models`
- 店员大脑：`xlx_clerk_brain.keys`

**1.3 旧数据迁移**
- 把四本账里已有的钥匙一次性搬进 `xlx_vendor_keys`，按厂商归组

**1.4 模型池骨架 + 首批厂商**
- 统一适配器接口
- 统一模型目录（一份清单，对话与短剧共用）
- 首批适配器：快手可灵、阿里云百炼

## 4. 第二层 · 工作台层

**界面**

1. 流水线换皮（`src/drama/auto.js`）——布局骨架、关卡流程不动，只换视觉
2. 项目中心 LibTV 首页（`src/drama/home.js`）——工程卡片 + 资产入口
3. 导演台无限画布 + 节点（`src/drama/manual.js`）——五类节点 + 连线 + 画布内合成导出
4. 造型室（新建）——容器，装下面的能力

**能力（装在造型室里）**

1. 三视图：正 / 侧 / 背，治崩脸
2. 场景卡：场景身份锚点
3. 多参考：每镜最多 3 张（依赖 Seedance 2.0）

**出层标志**：三个台新长相、新能力全部到位。

## 5. 第三层 · 3D-BOX（AI 满血）

**工具清单**

1. 多机位 9 宫格
2. 大师运镜
3. 灯光相机
4. 多角度
5. 精准编辑（依赖 Seedance 2.5）

**实现路线**：提示词模板 + 多参考图 + 并行调用。把「机位 / 灯光 / 角度」抽成统一接口，AI 生成是它的第一种实现；将来上真 3D 只需新增一种实现，上层不动。

**出层标志**：五个工具在导演台可用。

## 6. 门外

**工程类**

1. 真 3D 满血：真 360 度机位、真灯光（需引 3D 场景引擎，如 Blender；后置可选）
2. 多人实时协作 + 版本管理
3. Agent Skill / CLI 入口

**非工程类**

1. 垫资模型池（与厂商签约）
2. 社区 / 模板市场运营

## 7. 贯穿线 · 模型池铺满

第一层把骨架（适配器接口 + 模型目录）建好后，按同一套动作逐个加厂商、加模型，加多少算多少，不单独占层名额。
